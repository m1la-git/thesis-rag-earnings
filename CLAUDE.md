# CLAUDE.md

Agent guidance for this repository. The design, results and layout are in
`README.md`; read it first. This file holds only the rules an agent must follow.

This is a bachelor thesis (TUM, Management & Technology): a controlled
experiment on how retrieval design affects RAG answer quality over earnings call
transcripts. Kamila Bekkozhina is the author and directed the work throughout;
Claude Code assisted with code, scripts and drafting under her direction. The
account of AI use is the thesis appendix, `thesis/chapters/99_Appendix.tex`,
section "Use of Generative AI".

## Experimental integrity (non-negotiable)

- **Vary one thing at a time.** Only `chunk_size`, `retrieval_strategy` and
  `indexing_representation` differ between conditions. Corpus, benchmark,
  prompt, generator, top-k, embedding model, temperature and seeds are held
  constant.
- **Everything is config-driven.** Never hardcode a chunk size, strategy, model
  name or prompt. Module constants are cross-checked against `configs/base.json`
  by `run_experiment.validate_config_matches_code`.
- **Frozen, do not change:** the metric definitions in `src/evaluate.py`, the
  enrichment format in `src/index.py`, the prompt and abstention string in
  `src/generate.py`, the corpus (`data/corpus_manifest.json`) and
  `benchmark/questions.jsonl`. Changing any of them changes what every scored
  record means.
- **The five invariants in README.md hold.** Above all: anchor matching reads
  `chunk["text"]`, never `index_text`; the generator never sees the enriched
  string.
- **A scorer defect found after results exist is reported, not fixed.** Never
  loosen the abstention match or any classifier rule mid-experiment. Record it
  and ask.
- **Stage 1 is generator-independent and is never re-run for a generator
  change.** `results/retrieval/` must stay byte-identical;
  `analysis/verify_invariant5.py` checks it against the committed files and
  writes only to a scratch directory.

## The three generator runs

- `qwen3.8-27b@q8_k_xl` is the only reported generator. Every Stage 2 number in
  the thesis comes from `results/tables/qwen3.8-27b_q8_k_xl/` and
  `analysis/qwen3.8-27b_q8_k_xl/`.
- `qwen3.8-27b@q4_k_xl` is the regression baseline. `scripts/validate_all.py`
  is pinned to its figures **on purpose; do not re-pin it to q8.**
  `check3_attribution_postfix.py` and `fix_attribution.py` are q4-only by nature
  (they compare against `results/tables/prefix/`, the frozen pre-fix tables).
- `qwen3.8-flash-next` is a robustness check only. No manual review, no failure
  taxonomy, and no difference is attributed to any property of the model.
- The thesis makes no cross-model or cross-quantization comparison. Never write
  one.

## Paths and artifacts

- All model-scoped paths come from `src/model_paths.py`. The generation cache is
  keyed `results/generation/<model_slug>/<condition_id>/<question_id>.json`.
- `analysis/` is split three ways: `stage1/` if no generator was called,
  `<model_slug>/` if one was, and untracked `benchmark_authoring/` for benchmark
  construction material. A cross-arm document belongs to the arm being
  compared, not the baseline.
- Pinned expectations are data in `analysis/expectations/<slug>.json`, never
  auto-populated from a run. A missing expectation set is FIRST RUN, never a
  pass. Assertions pin set membership, not only counts.

## Numbers

- **Before quoting any number, find it in `analysis/claims_map.md`** and check
  its arm and its twins. Twins (one name, two populations) are the most common
  error in this project.
- The thesis cites numbers only through macros generated by
  `scripts/build_thesis_macros.py` into `thesis/generated/`. Never hand-edit
  `generated/`. `--check` must pass.
- Before moving a number from one place to another, re-derive it from the
  artifact's own tables, not from a summary of it.

## Benchmark authorship

Candidate questions and anchors were generated by a language model under rules
the researcher wrote; the researcher reviewed every pass and made every
accept-or-reject decision (`benchmark/benchmark_process.md` §10.1). Never
describe the questions as manually authored. Claude Code does not fill in
labels, reference answers or faithfulness judgments.

## Verifying a change

```
python scripts/validate_all.py --with-tests      # full run, including verify_invariant5
python scripts/validate_all.py --fast --with-tests   # skips verify_invariant5 only
python scripts/build_thesis_macros.py --check
```

A skipped job reports SKIP, never PASS.

## Thesis and Overleaf

- `thesis/` is synced with the TUM Overleaf project only through
  `scripts/sync_overleaf.py`. The Overleaf remote prohibits force pushes; never
  push to it any other way.
- Floats go after the references, one per page (`chapters/98_TablesFigures.tex`),
  with an "Insert Table N about here" placeholder in the prose.

## Secrets

`LMSTUDIO_API_KEY` and `LM_STUDIO_MODEL_NAME` live in
Windows user environment variables, never in a file in this repo.
`LM_STUDIO_BASE_URL` is host configuration with a localhost default, set in the
environment or in the ignored `.env`. Never read,
cat, echo or print the value of a key or token; reference it through environment
expansion (e.g. `$env:LMSTUDIO_API_KEY`) so the value never appears in output.
